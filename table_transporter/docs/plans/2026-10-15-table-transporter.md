# Plan: Table Transporter (YKB Oracle tablo taşıma)

## Context
YKB içinde ekiplerin Oracle DB'ler arasında hızlı ve **anonimleştirilmiş** tablo taşıyabileceği bir web uygulaması. Kişi LDAP (AD, KFS) ile girer, kaynak ve hedef DB'yi tnsnames.ora alias'larından seçer, iki DB için ayrı kullanıcı/şifre girer, tablo + kolon seçer, kolon başına anonimleştirme kuralı belirler, en çok 5.000.000 satır taşır. Her taşıma SQLite'a loglanır; hedefte 7 günü dolan tablolar tespit edilir ve DBA için DROP script üretilir. **Uygulama hiçbir koşulda silmez:** yalnız SELECT, CREATE TABLE, INSERT. Dizin boş (greenfield), git yok, makinede Docker/Oracle/LDAP yok → testler sahte bağlantıyla; gerçek deneme kullanıcının iş PC'sinde, sonra OpenShift dev namespace.

**Ne yapılacak:** FastAPI + python-oracledb (Thin) + ldap3 backend, React + Vite + TS sihirbaz arayüzü (YKB mavisi, logo), SQLite log, zamanlanmış varlık kontrolü, OpenShift'e hazır imaj ve manifestler.
**Kabul ölçütü:** (a) silmeme test paketi yeşil (guard, statik tarama, sahte DB'de çalıştırılan her SQL izin listesinde); (b) sahte DB ile 1M satırlık uçtan uca taşıma (create + append + iptal + 5M+1 reddi); (c) `pytest -q` ve `pnpm typecheck && pnpm test` yeşil; (d) playwright-cli ile sihirbazın mock API'ye karşı uçtan uca gezilmesi + ekran görüntüleri; (e) senin PC'nde gerçek DB'de küçük tabloyla deneme, ardından 5M satır < 5 dk hedefi (ağa bağlı).

## Kullanıcı kararları (alındı)
Temizlik = tespit + uyarı + DROP script (DBA elle çalıştırır) · Varlık kontrolü = senin vereceğin servis hesabı (alias başına kimlik, yalnız sözlük okuma) · Log = SQLite · Yığın = Python + React · Önce localhost, sonra OpenShift dev · 5M aşımı = önceden bilgilendir, filtre alanı, aşarsa "daha dar filtre girin" yönlendirmesi (taşıma başlamaz) · Saklama = sabit 7 gün · LDAP = `ldaps://ldaps.kfs.local:636`, Base DN `OU=BTUsers,OU=GMUsers,OU=KFS,OU=Users,OU=KFS,DC=kfs,DC=local`, domain KFS, TLS 1.2, CERT_NONE, 10 sn zaman aşımı.

## Kararlar
1. **Silmeme garantisi, 7 katman.** (1) SQL yalnız `oracle/sql_templates.py`'de sabit şablonlardan `Stmt` (frozen dataclass, modül-içi sentinel) olarak üretilir; serbest SQL hiçbir yerde yok. (2) `SafeConnection` ham `str` kabul etmez; `execute/callproc/callfunc`, ham connection/cursor dışarı açılmaz. (3) Guard: tek ifade, ilk token ∈ {SELECT, WITH…SELECT, INSERT, CREATE TABLE (kolon tanımlı; CTAS ve CREATE OR REPLACE yasak)}, `;` ve yorum yasak, değerler yalnız bind. (4) Tanımlayıcılar `re.fullmatch` + sözlükten birebir doğrulanır, `upper()` dönüşümü yok, çift tırnakla yazılır. (5) `import oracledb` yalnız `safe_connection.py` / `pools.py`; AST taraması ayrıca `callproc`, `callfunc`, `getattr`, `importlib`, `__import__` ve yasak anahtar sözcüklü string sabitlerini yakalar (DROP yalnız `cleanup/drop_script.py`'de, o dosya hiçbir DB modülü import etmez). (6) Append hedefi ALL_TABLES'ta gerçek TABLE olmalı (view/synonym değil) ve ENABLED trigger'ı olmamalı (trigger DELETE çalıştırabilir); hedef kullanıcının şemasında şema-seviyesi trigger varsa CREATE reddedilir. (7) Filtre serbest WHERE değil: kolon + operatör + değer satırları (değer bind) — serbest WHERE'de kullanıcı fonksiyonu çağrılıp kaynakta DML/DDL yapılabilir. Reddedilen: sqlglot (şablon sayısı ~10, gereksiz bağımlılık).
2. **Atomiklik.** Append = işe özel tek bağlantı, autocommit kapalı, `executemany(batch_size)`, commit en sonda; hata/iptal → `finally` içinde açık rollback, rollback bitene kadar `cancelling`, bağlantı ancak sonra bırakılır → hedef ya hiç değişmez ya tam yazılır. Create = CREATE TABLE → **hemen** `tracked_tables` kaydı (OBJECT_ID + CREATED ile, yükleme başlamadan) → `direct_path_load` (batch başına örtük commit); hata → `partial`, DROP listesine girer. ORA-00955 (ad dolu) → iş `failed`, tablo izlenmez. Thick (NNE) modda create de executemany kullanır.
3. **Oracle şifresi saklanmaz.** Bir kez `create_pool`'a verilir; oturum yalnız pool referansı tutar. Pydantic `SecretStr`; 422 handler `input` alanını atar; hata gövdesi yalnız `{error, detail}`; debug kapalı; testte yanıt + logda şifre aranır. Çalışan iş kendi pool referansını tutar → logout/TTL işi öldürmez (logout'ta "işiniz sürüyor, iptal edilsin mi?" sorulur).
4. **LDAP (AD).** Kullanıcı adı `^[A-Za-z0-9._-]{1,64}$`, boş/boşluk şifre bind denenmeden 401 (kimliksiz bind açığı). `KFS\kullanici` simple bind, LDAPS TLS 1.2, 10 sn; ardından kendi kimliğiyle Base DN altında `(sAMAccountName=<escape_filter_chars>)` araması **tam 1 sonuç** dönmeli (Base DN dışındaki kullanıcı giremez) → displayName, memberOf. Opsiyonel `LDAP_ALLOWED_GROUPS`, `LDAP_ADMIN_GROUPS` (admin tüm işleri ve temizliği görür). CERT_NONE senin ayarın; `LDAP_CA_FILE` verilirse doğrulama açılır.
5. **Oturum.** Süreç içi sunucu oturumu, çerez HttpOnly + SameSite=Strict + Secure (`TT_COOKIE_SECURE`, localhost'ta kapatılabilir), CSRF başlığı, 30 dk boşta TTL (açık SSE/aktif iş canlı tutar). Tüm iş uçlarında sahiplik kontrolü (başkasının işi → 404).
6. **Hız.** Okuyucu thread `fetch_df_batches` (Arrow, ~100k satır) → `Queue(maxsize=4)` → anonimleştirme → yazıcı (direct path ~500k–1M batch / executemany 50k). CPU yoğun kurallar (hmac, num_token) benzersiz-değer önbelleği; yetmezse ProcessPool. Arrow tip eşlemesi açık: NUMBER(p≤18,0)→int64, NUMBER(p,s)→decimal128, ölçeksiz NUMBER kayıpsız yol (2^53+1, 38 hane gidiş-dönüş testi; float64'e düşmesi yasak). Desteklenen tipler: NUMBER/FLOAT/BINARY_*, CHAR/VARCHAR2/NCHAR/NVARCHAR2, DATE/TIMESTAMP; LOB/RAW/LONG/XML/TZ'li TIMESTAMP kapsam dışı (UI'da "taşınamaz" + `exclude`).
7. **5M limiti.** Tablo listesinde NUM_ROWS tahmini ve ">5M" rozeti; Tablo adımında baştan bilgi bandı; filtre oluşturucu + "Satır sayısını hesapla" (COUNT, zaman aşımı + iptal) → gösterge çubuğu; >5M ise İleri kilitli ve "Seçiminiz X satır, sınır 5.000.000. Lütfen filtreyi daraltın." Sunucu da başlatmada yeniden sayar ve reddeder; okuma sorgusunda `FETCH FIRST :limit ROWS ONLY` sert tavan, yazıcı sayacı → hiçbir yolda 5M aşılamaz (kaynak sayımdan sonra büyürse tam 5M yazılır, uyarı loglanır).
8. **Anonimleştirme kuralları.** `keep, exclude, null, constant, mask(show_last), hmac, num_token, date_shift, random`. hmac = HMAC-SHA256 (anahtar sunucuda, ≥32 bayt, kararlı → aynı party_id tüm tablolarda aynı sonuç, join korunur). num_token = anahtarlı Feistel + cycle-walking ile **birebir** sayısal permütasyon, basamak sayısı korunur (küçük alanlarda kapsamlı birebirlik testi). PK/UNIQUE kolonda (ALL_CONS_COLUMNS) yalnız birebir kurallar: keep, num_token, hedef uzunluğa sığan tam hmac; random/constant/null/mask reddedilir. NOT NULL hedefte null/boş constant/boşa düşebilen mask reddedilir ('' = NULL). Çıktı hedef uzunluğuna (BYTE/CHAR) sığmalı. CHAR dolgusu kural öncesi kırpılır. date_shift: satır başına tek ofset, seçilen çapa kolonunun HMAC'inden; satırdaki tüm tarih kolonları aynı kayar (BAŞLANGIÇ<BİTİŞ korunur), DATE sınırlarında clamp. Önizleme: 5 satır önce/sonra + NULL sayısı.
9. **Hedef tablo.** Create yalnız hedef kullanıcının kendi şemasında; DDL kaynaktan tip + uzunluk + açık BYTE/CHAR + NOT NULL; DEFAULT/IDENTITY/virtual kopyalanmaz (UI'da yazılı). Ad önerisi `<TABLO>_ANON_<yyyymmdd>`, varlık kontrolü → 409; ad uzunluğu DB sürümüne göre (12.1: 30, 12.2+: 128). Aynı hedefe eşzamanlı iş kilidi. Append: virtual/IDENTITY/hidden hedef kolonlar yazılamaz; uyumluluk raporu (ok/warn/error); Özet'te hedef `ŞEMA.TABLO` elle yazılarak onaylanır, başka şemaysa ek uyarı.
10. **Temizlik (7 gün).** Servis hesabı `config/service_accounts.toml` (gitignore; OpenShift'te Secret) `[default]` + `[alias.X]`. İş bitince tablo servis hesabıyla bir kez görülmeli (`verified_visible_at`); görülmeden asla "silindi" sayılmaz (`unverifiable`). Kontrol OBJECT_ID + CREATED eşleşmesiyle (aynı adla yeniden yaratılmış tablo DROP listesine girmez). Durumlar: active → expired_present → deleted_verified / unverifiable. DROP script yalnız uygulamanın yarattığı ve eşleşen tablolar için, başlık yorumuyla indirilebilir metin. Zamanlayıcı lifespan içinde asyncio döngüsü (APScheduler yok). Açılışta `running` kalan işler `failed/partial` yapılır.
11. **UI.** Sihirbaz: Giriş → Bağlantılar (kaynak/hedef yan yana kart, aranabilir alias, ayrı kimlik, "Bağlantıyı test et") → Tablo (arama, sayfalama, filtre, sayım) → Kolonlar (kural editörü; toplu seçim, ad kalıbından öneri: TCKN/IBAN/AD/SOYAD/TEL/EMAIL/PARTY_ID/MUSTERI_NO; "önceki işten kuralları kopyala"; önizleme) → Hedef (yeni/mevcut, uyumluluk) → Özet & onay → İlerleme (SSE + 2 sn polling yedeği, satır/sn, ETA, iptal, aria-live; "işiniz arka planda sürer, Geçmiş'ten izleyebilirsiniz") → Geçmiş / Temizlik. YKB mavisi `#004B93` token olarak (kurumsal kılavuzla teyit), logo `frontend/public/brand/` (resmi dosya gelene kadar yer tutucu). Hata mesajları Türkçe, ORA kodları eşlenir. Rehber: impeccable + emil-design-eng SKILL.md (builder'a yol verilir), erişilebilirlik kontrolü ui-ux-pro-max ile (ana oturum).
12. **Canlı ortam koruması.** tnsnames'te 4 alias var: DEMO_DEV, DEMO_TEST (aynı host, 1453), DEMOLIVE (canlı, SCAN), TESTDB_DENEME (srv_demo1db, 1521). `TT_TARGET_DENY_ALIASES=DEMOLIVE` → canlı DB yalnız **kaynak** olabilir; hedef listesinde görünmez, sunucu da reddeder. Kaynak canlıysa UI anonimleştirilmemiş (keep) kolonlar için ek onay ister. Parser host/değerlerdeki boşlukları kırpar, `ALIAS=` ve `ALIAS =` biçimlerini kabul eder. Gerçek dosya `config/tnsnames.ora` (git dışı); testlerde kurgusal host adları kullanılır.
13. **Dağıtım.** Yerel: `run_local.ps1` (uvicorn tek worker, frontend build'i FastAPI sunar). OpenShift: çok aşamalı Containerfile (node build → python slim, rastgele UID uyumlu), Deployment **replicas=1** (süreç içi oturum + SQLite), PVC (/data SQLite), ConfigMap (tnsnames.ora + gizli olmayan ayar), Secret şablonu (servis hesapları, HMAC, oturum anahtarı), Service, Route (edge TLS). Pod yeniden başlarsa kullanıcılar yeniden girer; işler kurtarma kuralına göre işaretlenir.

## Riskler
- Thin mod NNE desteklemez: DB'lerde `SQLNET.ENCRYPTION_SERVER=required` ise Thick (Instant Client) gerekir, direct path olmaz, hız düşer. DB sürümü ≥12.1 şart.
- Append'te 5M satır tek transaction → undo dolabilir (ORA-30036); uzun okumada ORA-01555. Özet'te tahmini boyut uyarısı.
- LDAP CERT_NONE ortadaki adam saldırısına açık (senin ayarın; CA dosyası verilince kapanır).
- Oracle'da sahip kendi tablosunu her zaman düşürebilir; garanti uygulama katmanındadır, DB yetkisiyle değil. DB-seviyesi DDL trigger'ları uygulamanın görüş alanı dışında.
- Feistel num_token kriptografik şifreleme değil, takma adlandırmadır; küçük değer uzaylarında anahtar gizliliği esastır.
- Yerelde Oracle/LDAP/Docker yok: gerçek doğrulama senin PC'nde ve OpenShift'te.
- Geri dönüş: her dalga ayrı commit; sorunlu paket geri alınır.
